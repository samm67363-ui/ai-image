# AI Image Classifier

A full-stack web app where users upload an image and get an instant AI
prediction (class name + confidence score + top 5 predictions), powered by
a pretrained **ResNet18** model.

- **Frontend:** React (Vite), Axios
- **Backend:** Python, FastAPI, Uvicorn
- **Model:** `torchvision.models.resnet18` with pretrained ImageNet weights

## 2. Requirements

- **Node.js** v18+ and npm
- **Python** 3.10 or 3.11 (recommended — avoids PyTorch wheel issues on very new Python versions)
- **Git**

---

## 3. Backend Setup

```bash
cd backend

# Create a virtual environment
python -m venv venv

# Activate it
# Windows:
venv\Scripts\activate
# Mac/Linux:
source venv/bin/activate

# Install dependencies (this downloads PyTorch — can take a few minutes)
pip install -r requirements.txt

# Run the server
uvicorn main:app --reload
```

The backend will start at **http://localhost:8000**.

Test it's alive by visiting **http://localhost:8000** in a browser — you
should see:
```json
{"status": "ok", "message": "AI Image Classifier API is running."}
```

Interactive API docs (auto-generated by FastAPI) are at
**http://localhost:8000/docs** — you can test the `/predict` endpoint
directly from there by uploading a file.

---

## 4. Frontend Setup

```bash
cd frontend

# Install dependencies
npm install

# Copy the env example and adjust if needed
cp .env.example .env

# Run the dev server
npm run dev
```

The frontend will start at **http://localhost:5173**.

Open that URL in your browser — you should see the AI Image Classifier
home page. Upload an image and click **Predict**.

## 5. Testing the Full Flow

1. Start the backend (`uvicorn main:app --reload` inside `backend/`, with venv activated).
2. Start the frontend (`npm run dev` inside `frontend/`).
3. Open **http://localhost:5173**.
4. Drag & drop (or click to browse) an image — JPEG/PNG/WEBP/BMP, under 8MB.
5. Click **Predict**.
6. You should see a loading spinner, then a result card with the class name,
   confidence %, and a bar chart of the top 5 predictions.
7. The prediction should also appear in the **Prediction History** section below.

### Error cases to try
- Upload a non-image file (e.g. a `.txt` renamed to `.jpg`) → should show a validation error.
- Stop the backend server and click Predict → should show "Could not reach the backend server."
- Upload an image over 8MB → should show a size error before it even reaches the backend.

## 6. Common Errors & Fixes

| Error | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: No module named 'app'` | Running uvicorn from the wrong folder | Make sure you're inside `backend/` when running `uvicorn main:app --reload` |
| CORS error in browser console | Backend not allowing frontend origin | Confirm `CORSMiddleware` is present in `main.py` (already included) |
| `pip install` fails on torch | Python version too new/old | Use Python 3.10 or 3.11 |
| Blank page on frontend | `npm install` not run, or wrong Node version | Run `npm install` again; confirm `node -v` is 18+ |
| Prediction takes a long time on first request | Model is loaded once at server startup — first request after starting the server may be a little slower while things warm up | This is expected; subsequent requests are fast |

## 7. Deployment (GitHub → Render → Vercel)

This repo is already configured for a no-terminal, dashboard-only deploy:
`render.yaml` sets up the backend on Render, and `frontend/vercel.json`
sets up the frontend on Vercel. You never need to run these locally —
everything below happens through the GitHub, Render, and Vercel websites.

### Step 1 — Push this repo to GitHub
Easiest without a terminal: go to github.com → **New repository** → then
use GitHub's **"uploading an existing file"** link on the new repo's page
to drag and drop the entire unzipped `image-classifier` folder contents.
(Or, if you have GitHub Desktop, use that instead of the command line.)

### Step 2 — Backend on Render
1. Go to render.com → **New → Blueprint**.
2. Connect your GitHub repo. Render will detect `render.yaml` automatically
   and pre-fill the service (root dir `backend`, build/start commands, Python
   version) — just click **Apply**.
3. Wait for the first deploy. It installs PyTorch, so it can take several
   minutes. Once live, Render gives you a URL like
   `https://image-classifier-backend.onrender.com`.
4. Visit that URL — you should see
   `{"status": "ok", "message": "AI Image Classifier API is running."}`.

### Step 3 — Frontend on Vercel
1. Go to vercel.com → **New Project** → import the same GitHub repo.
2. Set **root directory** to `frontend` (Vercel auto-detects Vite from
   `vercel.json`).
3. Add an environment variable:
   - `VITE_API_URL` = your Render URL from Step 2 (e.g.
     `https://image-classifier-backend.onrender.com`)
4. Deploy. You'll get a URL like `https://image-classifier.vercel.app`.

### Step 4 — Connect them (CORS)
Go back to the Render dashboard → your backend service → **Environment**
tab → edit `ALLOWED_ORIGINS` to your real Vercel URL, e.g.:

```
ALLOWED_ORIGINS=https://image-classifier.vercel.app
```

(Preview deployments on `*.vercel.app` are already allowed automatically
via a regex in `main.py`, so pull-request preview URLs keep working without
extra config.) Save — Render redeploys automatically.

### Step 5 — Test it
Open your Vercel URL, upload an image, click **Predict**. The first request
after Render has been idle (free tier sleeps after inactivity) can take
30–60 seconds while the server wakes up and reloads the model — that's
expected, not an error.

## 8. Notes on the Model

- Uses `torchvision.models.resnet18` with `ResNet18_Weights.DEFAULT` (pretrained on ImageNet, 1000 classes).
- Preprocessing (resize, center crop, normalize) uses the exact transform pipeline bundled with the weights, via `weights.transforms()` — so it matches how the model was originally trained.
- Class names come from `weights.meta["categories"]`, so no separate labels file is needed.
